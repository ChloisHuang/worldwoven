## 原物件与动作

`createTellerTools` 提供一册原账本、一把原笔、一座十一杆算盘。正式装配时必须省略 `china-money-house.js` 中从 `Open ledger has a crease` 至 `Enclosed store` 之前的旧装饰，只创建这组实例，并置于静态打包之外。当前只在只读生产场景装配夹具中精确替换，生产文件未改。

初始布置调整，不算NPC已完成劳动：算盘原位置/尺寸保持，旋转180度让下珠朝向工作人员；原笔移至账本右侧，落到柜台实际顶面，墨砚降低消除旧悬空。工作站位向柜台靠近6厘米，完整0.25米身体半径离原柜体仍有3厘米；原返岗位不变。

使用已上线 `handoffLean=.5`、`handoffDip=.035` 和原IK。未改变骨长、身体比例、共享角色或银行服务代码。先逐币读账，再逐币算盘核算，最后拾原笔落记、归笔、原路返柜台。工资仍为完整单8文设计费率。

休眠合同版本2明确四币各核算2秒（共8秒），连同核查8秒、落记2秒共18秒有效接触劳动。旧版本1从未接生产；新控制器不默默接纳旧休眠阶段。珠位由真实冻结报告的 cash+bank+held 合计决定，不用空闲动画计工。十一杆以两段十进制窗口核算，避免大额安全整数截断。期末接触检查要求末态已真实达到，存档仍只有原顶层订单为权威。

工具核验包含原必需节点、父子关系、可见性、原网格/顶点/索引、局部变换以及活动珠位和原笔姿态。空Group、被挪动/隐去/篡改工具不能作为有效劳动；落记检查实际锥形笔尖落在纸张顶面。

- `node --experimental-vm-modules tests/china-teller-physical.cjs`：实际男性/女性rig原物件接触、原骨长、缺失/隐藏/变形反例、双窗口大额正确性、中途恢复及三日模型。

两个供给模型分别用零交易账本、由原金融API创建的真实序列测试夹具。均用原模拟时钟完整推进三个游戏日（步长取整6171.5加载秒），每天预留开柜和不可控制时段。使用同一真实rig、工具和控制器，共54秒接触劳动，原单收入8/8/8；每天使用账户支付端口扣模型餐费6，余额2/4/6。玩家源账从头至尾不变。模型只沿柜台后方清晰通道做有界移动；不是生产main的完整碰撞、其他NPC客流、实际送餐/食用、厕所或多日全世界验收。
