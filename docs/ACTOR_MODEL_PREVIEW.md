# C01 opt-in actor integration

Development only. First explicitly import `source/game/complete-adult/register.js` in the development entry; then synchronous `createCharacter({...appearance, modelPreview:'complete-adult-head-v1'})` uses the current candidate head. Omitted, unknown, or not-yet-registered selection stays legacy; registration alone selects no actors. No production call site enables it, and nothing in this branch is an aesthetic approval. `root.userData.characterModel` reports applied/fallback and the asset version; saved appearance fields and scoring are unchanged.

`complete-adult-head-v1` is **head-only** and keeps every original body/clothing mesh. A separate `modelPreview:'complete-adult-pair-v1'` ports the existing soft-shoulder/folded-collar and gown refinements only for the exact two French representatives (masculine-lean / side-part / court-frock-coat and feminine-slender / chin-bob / court-gown, casual). Other pair-selection requests fall back unchanged. It is not a cultural wardrobe replacement.

- Both existing masculine body presets support side-part; both feminine presets support chin-bob
- All four body presets also support the retained low bun through a shared candidate-derived attachment envelope
- Casual cultural wardrobes are retained. France male artist/beret also has the same envelope boundary; chef/gardener hats remain explicit fallback
- Braid, shoulder-wave, swept-short and cross-form side-part/bob combinations remain explicit fallback. No all-NPC rollout is claimed
- The existing official cap, emperor/consort ornaments and Jinyi cap attach to the same real head bone through one shared fit hook. Only actual Chinese official `cn-minister-works` and consort `cn-consort-yue` are visually checked in this stage
- Official moustache/goatee are retained, mapped between original/candidate lip/chin landmarks and fitted to the candidate front triangle surface during template creation. They are never removed as generic head meshes

Asset provenance is pinned to art/adapter commit `a0b2aa3`; neutral head/hair arrays were not resculpted. The six-trait pure morph implementation is retained. Runtime imports only browser `.js` modules, static baked geometry and shader helpers; no source OBJ, research image, Node file reader or scalp authoring/raycast function is shipped. CC0/upstream text and provenance are under `source/licenses/complete-adult` and copied into build output.

The two existing skinned draw buckets and skeleton remain. Preview skin uses a separate lazy shared material: importing/using it cannot patch the legacy material. Versioned template keys separate preview from legacy; unsupported requests reuse legacy templates. Body/clothing source ranges retain their positions, normals, colors and skin weights byte-for-byte. The new head has 46 fully chest-anchored collar vertices and 52 cervical blend vertices.

## Current visual and loading limits

The Chinese-role images are compatibility evidence, not overall art acceptance: 月容's retained low bun exposes a long straight neck against the old shoulder/collar silhouette, and the inherited official hat is visually large. Anatomy, head joint and chest boundary remain fixed while the new head/neck asset is pending. Do not move the skull or joint according to collar height; lower necklines reveal more skin. No claim that these roles reproduce the complete French silhouette is made.

`characters.js` imports only a lightweight synchronous registry. The approximately 1.51 MB of candidate form/hair text loads only when the separate development registration entry is explicitly imported. The ordinary production build graph excludes the candidate adapter, mesh assets and finish/clothing helpers; no global bundler change or production UI was added. The development renderer imports the registration entry directly from source. Preview registration keeps the same synchronous actor API and existing fallback behavior.
