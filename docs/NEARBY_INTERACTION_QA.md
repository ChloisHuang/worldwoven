日期：2026-10-07。范围：共享对象动作提示与人物交谈呈现；不改变存档、订单、交易、关系或 NPC 行为。

## 审图入口

`/qa/nearby?case=cn-nearby` 自动打开 852×393 的独立 iframe；其他基础状态是 `cn-menu`、`jp-nearby`、`conversation`。界面提供重开、测量、真实按钮点击、菜单关闭及内容滚动。`frame=1` 仅打开该独立视口。

画面必须明确标为“非实机 · Mesa 背景 + 真实产品 DOM/CSS · 仅内存选择”。背景 PNG 来自生产场景正常第三人称镜头；前景直接挂载候选产品 UI 模块，没有另外重画菜单。业务以有限内存夹具承接回调，不运行游戏 main，不读取或写入游戏存档。

QA 发布应使用隔离的候选模块和 CSS，保持生产入口、线上版本及站点受众不变。PNG 和 JSON 为独立 QA 静态资源；打包后的入口须从 `/qa/nearby/` 获取它们。

## 原神实机参考

以下均是 HoYoLAB 官方社区平台上的玩家实机截图，不是官方设计规范。已联网取得原图并查看像素，仅借鉴信息组织，不复制游戏素材进入产品。

1. [移动端炼金台：Timaeus 与 Craft 两行目标](https://www.hoyolab.com/article/17529935)。正常第三人称画面中，相邻人物与物件有各自可读、可选的行；多目标没有退化成无解释圆点。
2. [营火旁明确显示 Cook](https://www.hoyolab.com/article/581350)。厨师帽图标搭配动作文字；F 键提示独立于动作名，点击前就能判断会发生什么。
3. [凯瑟琳：服务与上下文话题](https://www.hoyolab.com/article/16608181)。领奖、派遣、人物特定话题和告别分成独立行；服务图标、说话人姓名及台词承担不同信息层级。

据此采用的设计判断：近场首先露出对象与动作文字；多个候选保持独立可读；NPC 交谈体现眼前人物与已存在上下文；用正常游玩视角审查目标、角色和文字能否一起理解。ARIA label 或悬停 title 不能替代触屏上的可见文字。
