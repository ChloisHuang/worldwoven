- 收到新需求或用户反例时，立即新增条目或重新打开原 ID；不得等下一次大版本汇报才登记

- 只有实际完成并发布的条目填写 `completed_at`；开发完成或单项测试通过不能提前计为完成
- 以 UTC+8 的 `completed_at` 计算，完成超过 24 小时的条目在维护时移到 [完成项归档](checklist-archive/README.md) 下当月文件，保留稳定 ID、完成时间、修复/验证提交、发布版本与证据。主清单移除其详细正文，仅保留归档入口
- 旧问题再次出现时恢复原 ID 到主清单，并链接原归档记录；不能删除失败证据或用新 ID 隐藏回归
- 主清单聚焦未完成及最近24小时完成项；发布历史也按同样规则保留近期记录，较早内容放入归档
- 每个正式修复提交应包含对应 checklist 更新；纯测试分支的中间结果可以记为“修复中/待验证”，不能提前勾选
