# CN06 云来楼 · 本批范围与验证

## 建成内容

原东南书斋腾出的 x16..26 / z8..21 地块为同一栋三层建筑。北部公共梯厅有两组双跑折返梯、转身平台、连续洞口护栏和 1.8m 公共横廊；客卧不承担上楼路线。

- 一层：开放酒楼，四把可坐餐椅、两组实腿餐桌、茶器和迎客茶案
- 二层：两间独立私门客房，各有可躺客榻、可更衣衣柜；公共候坐椅
- 三层：成年诗词吟诵厅、两把听席、独立宴饮雅间及两把宴饮椅；七弦琴案、织物背景和金边地毯
- 三层都有完整墙体、真实窗洞、天花板和灯具；外立面三层牌匾与青绿重檐对应实际楼层
- 新身份：许安（cn-tavern-host，38岁掌柜），柳清弦（cn-tavern-reciter，27岁艺者）。使用既有安全茶饮/持书姿态、实际短程走动及归位，不新增人物或姿态引擎
- 静态几何按层与屋顶合批；没有向西增加地面廊柱或门廊，x14.9 巡查线保留

客栈订房/支付、点单上菜、真正奏琴/舞蹈动作、关系邀约及年龄/家庭准入规则不属于这次实现。琴是可辨识陈设；当前表演是持书吟诵与玩家听赏，不宣称已有声音或完整演艺经营。床的进度不计作住宿服务。

## 定向验证

运行脚本：`node --experimental-vm-modules tests/china-tavern.cjs`。`TAVERN_MESA=1`增加实际 Three/Mesa 截图；`TAVERN_STAFF_ONLY=1`和`TAVERN_VISUAL_ONLY=1`仅重跑未完成的员工或视觉/楼层标签部分。`TAVERN_BED_ONLY=1`只复验新兰房客榻接触和同机位画面。

已通过的生产 main 模拟 DOM 路线和交互：庭院→公共梯厅→酒楼；第一组楼梯上行；兰房私门→客榻躺下/起身→衣柜预览/取消；竹房私门；第二组楼梯上行；顶层听席坐/起；听赏开始/取消；两组楼梯连续下行→离楼。13个新增家具实例均注册，交互落点均未被碰撞遮挡。沿 x14.9、z7..24 的地面人体净空检查通过。

两名新增居民分别完成真实离岗走动和归位。原 NPC 路由末端按 0.16m 消耗，因此归位断言采用 0.18m；最初 0.08m 断言误报，未修改导航容差。员工定向场景 31.84秒、约558MiB。

正常4.6m TPS已看外观、酒楼、公共客栈厅、兰房床、竹房、顶层吟诵厅和听席。修掉新桌子误绘的实心碰撞外壳；琴案为实际收腰轮廓。楼层标签先按本楼 x/z 范围筛选再取最近高度，三层和两段楼梯中途不会误显示静宜后宫。新源几何边界断言避免器皿尺寸参数倒置产生超出地块的模型。

最后顶层相机及标签实际 Three/Mesa 定向复验41.25秒、约912MiB，只复验修过的物件、朝向、座椅画面与楼层标签；已过路线、旧门、其他国家、泡澡和原角色外观未重跑。此证据是实际 Three/Mesa 加模拟 DOM，未声称真实浏览器或 iOS 实玩验收。

客榻复核发现旧枕头处于背部下面、头却在枕后，造成背部拱起的视觉问题。已将薄圆角枕移到实际头部后侧，铺被延伸承托肩背，床垫/铺被边缘圆角、木框减薄；单个代表身体的实际 CPU 蒙皮点对真实表面射线复验：背4.02mm、臀4.00mm、后脑4.00mm、足跟4.00mm。随后生产 main 同一身体/同一侧向 TPS 机位复验通过：实际蒙皮点独立射线、床上/床下控制恢复及资源释放均通过，36.79秒、约870MiB。此检查只针对新客榻，不扩大到旧龙榻或所有外观。
