# W09 首批健康与照护接入

本系统中的「余烬倦怠」和「雾铃困倦」都是虚构游戏病症。阶段、体质、暴露量和恢复速度仅用于游戏平衡，不对应现实诊断、治疗方法或药物剂量。

## 实际玩法

- 玩家和地区内的真实 NPC 沿用原来的身份编号；健康不会重建人物、改衣着或降低玩家行走速度
- 症状出现在玩家地点卡下方和患病 NPC 的原有头顶状态中。坐下、躺下或已实际入座的泡汤休息会加快恢复；走向座位本身不算休息
- 医馆只有把原编号单对应的同号云纹包当面交付给玩家，才开始一段有限的支持性照护。写单、备好纸包、站在柜台附近、取消问诊均不产生此效果；重新读档不会重复领取效果。照护逐步帮助恢复，不会把病症立即清零
- 已有生活系统提供的饥饿和疲劳来自原系统的最近存档点。玩家只有健康用途的疲劳累积与休息恢复，未另建玩家饥饿、食物营养或卫生玩法

## 暴露从哪里来

健康世界不会随机给静态居民撒病。唯一新增的外来暴露来自日本汤馆的真实新来客：其实际到访时，固定的世界种子和来客编号决定是否曾在虚构「雾铃驿」停留。约十六分之一的旅途会有这段经历；这只产生一次有限暴露，其是否跨过该来客的发病阈值仍受稳定体质与阈值影响，并非每位经过者都会发病。

这段旅途与暴露记录跟随到访编号保存；重进地区、换装、重新载入同一来客不重新抽签或再次施加暴露。旧存档中已经发生的来访不会被追补暴露。永久居民不能凭空成为传染源，非传染的余烬倦怠也不会传给别人。

雾铃困倦只有发病阶段可以传播。每段实际模拟时间都用当前世界里的真实人物位置构成近距离接触：同一地区、脚下高度差小于 0.65、三维距离小于 2，且用当前场景墙体和门扇检查视线。不同楼层、隔墙、远处以及已离场人物不能隔空增加暴露；不按渲染帧数抽签。传染状态改变时，底层逻辑按事件分段推进。

## 存档与边界

玩家、已见过的永久 NPC 状态一直保留。来客仅保留八份近期健康与旅途记录，当前仍在汤馆的真实来客优先保留，不因住得久而被较新的离场者挤掉。来访编号水位防止被清理的旧来客重新触发旅途暴露。

健康每五秒模拟时间保存，并在离开地区、页面隐藏和页面离开时写入。换地区后，已知人物的病程可随当前游玩时间自然进展，但离场人物没有接触暴露；世界地图、后台和关闭游戏时不推演病程。状态描述展示症状与照护，不展示隐藏阈值和潜伏状态。

本批没有接入病假、请人代班或家庭照护。底层建议字段仍只是建议，任何现有岗位、轮休覆盖、工作订单和交班流程均继续由原系统负责。日本泡汤配料也没有被变成医馆照护。

## 检查范围

- `tests/game-health.mjs`：底层累计时间、阶段、局部接触、保存与恢复的六项检查
- `tests/game-health-world.mjs`：五项世界适配检查，覆盖视线/楼层、实际需要输入、跨地区保存、到访去重、有上限的来客记录、同号交付与照护去重
- `tests/game-health-main.cjs`：单个中国实际主程序场景中的症状状态、真实入座休息、早退取消、编号纸包柜台交付、保持速度外观、离场与重进，以及页面离开保存。使用模拟 DOM 与生产 Three，不代表真实浏览器或 iOS 验收

医馆建筑、上下楼路线、美术和守卫通道沿用医馆批次的独立证据，不在健康检查中重复建立地区或几何矩阵。
