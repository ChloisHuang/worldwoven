## Delivery and failure behavior

- `service-relationship-outbox.js` only acknowledges `{ok:true}` and passes a detached event. Callback throws or failed relationship saves leave the durable source replayable. A later business save compacts acknowledged pending rows.
- Tavern and Egypt include pending events in the same business transaction as the actual boundary. France persists pending source events before releasing its completed order. Salon saves the pending source and can reconstruct a settled session after interrupted post-settlement saving.
- Palace tea and royal kitchen retain original terminal order records; terminal simulation timestamps are saved in their controller envelope. Retries/reload use identical IDs and timestamps.
- Clinic retains a durable pending outbox. Bank embeds actual teller and simulation time in its original transaction request ID and replays from the durable ledger. Both underlying currency ledgers retain their full transaction history, validate every transaction on restore, and currently do not compact it; future ledger compaction must preserve pending relationship receipts.

## Shared state and actual behavioral integration

- `relationship-events.js` stores distinct directional liking, trust and aversion. Actual known observers and supporters are identities, not arbitrary counters. The only reputation used by an observer is their known evidence; no all-map reputation transmission. This is a shared ST07 social-state foundation, not completion of ST07's complete morality/health/stories scope.
- Each stable event ID is accepted once, including after reload and after the last 48 readable results are trimmed. All receipts remain durable. Source-confirmed fault is necessary for a negative failure effect; cancellation, refusal, insufficient funds and ordinary interruption are zero. Same observer/subject/source/kind effects cool down for 60 source-simulation seconds, including reload. Appearance never changes service effects or cancels distrust.
- All existing actual NPCs use individual saved or stable identity-seeded personality/values. New service deltas are projected over, not written into, legacy R99 NPC relations and R115 player-conversation totals. Original conversation ledgers remain the unique writer of conversation rewards.
- Existing NPC invitation target weights and acceptance read the projection at their original activity boundaries; W08 still selects the action before the target, with unchanged random draw count and action frequency. Existing real actors, available partners, work/urgent-need gates and cancellation paths remain in charge. There is no new all-pairs scan or fictional appointment.
- `social-attention.js` gives each observer deterministic preferences over all ten actual C02 geometry traits. Passing player attention uses personality, known relations/opinions/trust/aversion, known reputation, fatigue/hunger and current availability. Existing nearby visibility and same-floor gates still apply. Saved seeded 8–12-second opportunities drive brief 1.05–1.55-second looks; scene reload preserves their clock and draw state.
- Attraction and appearance acceptance require both actual recorded ages ≥18. Unknown age and minors retain ordinary respectful greetings without attraction. Distrust or an explicit boundary disables the appearance acceptance bonus. Existing real player-topic invitations and NPC-to-NPC invitations consume only a small bounded preference modifier, never consent or guaranteed acceptance.
- Known service history appears in the existing greeting, alongside existing conversation memory; hidden numerical bars are not added. There are no new intimacy, family, crime, pregnancy, country or occupation workflows.

The France full-meal test executes the actual main relationship-store construction with a deliberately stale snapshot writer. The writer is never called during the outbox acknowledgement, and the just-committed source envelope (including cleared paid order and closed meal) stays saved. Shared relation saves must continue to merge the already committed `saved` object instead of re-entering a producer's snapshot while that producer returns from persistence.

This finite implementation covers current real services, passing attention and the existing follow-on conversations. The checklist's separately recorded expansion to multiple relationship stages and multiple new legal interactions per stage remains open; no absent invitation/intimacy/argument UI is claimed to exist. No geometry, lighting, long economic chain, new occupation or visual character acceptance was changed or re-tested.

Permanent deduplication receipts retain exact event IDs with a boolean rather than duplicating every full event signature. Recent event bodies still detect conflicting callers; old IDs always suppress replays and are never LRU-evicted or replaced by collision-prone hashes. A representative 1,000 tavern IDs cost about 65 KiB JSON (roughly 130 KiB if the storage quota counts UTF-16). This grows with actual events and is not a bounded whole-game storage guarantee; future compaction must preserve out-of-order/pending source IDs, not use an unsafe global high-water mark. Source ledgers already serialize the whole save; this layer writes at actual event boundaries only, never per frame.

Salon preserves the original artist-to-customer willingness direction via a distinct `china-salon-guest` completed appointment/payment event. The original `china-salon` evaluates the artist's service in the opposite direction. These are separate aware facts and cannot also increment the legacy private relation when the shared callback is active.
